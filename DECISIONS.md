# Product Philosophy

### Decision 001

CommunicationGym is **not** an AI tool.

CommunicationGym is a daily communication training platform.

Artificial Intelligence exists only to make practice more effective.

---

### Decision 002

We optimize for **habit formation**, not feature count.

Every product decision should increase the likelihood that users return tomorrow.

---

### Decision 003

CommunicationGym should feel like a communication gym.

Not a classroom.

Not a course.

Not an exam.

Users train.

They don't study.

---

# Daily Workout

### Decision 004

The Daily Workout is permanently free.

This is the company's primary growth engine.

Premium features must never restrict access to the Daily Workout.

---

### Decision 005

Users complete **one Daily Workout every day**.

Quality over quantity.

We are building a daily habit rather than encouraging binge usage.

---

### Decision 006

Daily Workouts are personalized.

Topics are selected using onboarding preferences while maintaining enough variety to improve overall communication ability.

The wheel reveals today's workout.

It does not randomly generate one.

---

# User Experience

### Decision 007

The application should be usable by anyone.

No technical knowledge should ever be required.

If someone can comfortably use UPI,

they should comfortably use CommunicationGym.

---

### Decision 008

Every screen should answer one question:

> **What should I do next?**

Users should never feel lost.

---

### Decision 009

Every screen should have only one primary call-to-action.

Avoid decision fatigue.

---

# AI

### Decision 010

AI feedback should always encourage improvement.

Never embarrass.

Never shame.

Never discourage.

Users should finish every workout feeling motivated to return.

---

### Decision 011

CommunicationGym should never pretend to know something it cannot measure.

AI evaluations must be explainable and based on accepted communication principles.

Avoid fake precision.

---

# Gamification

### Decision 012

Rewards are based on consistency,

not perfection.

Completing a workout is always celebrated.

---

### Decision 013

Competition should motivate,

not intimidate.

Leaderboards should encourage participation from beginners as well as advanced users.

---

### Decision 014

Progress should be visible.

Users should always understand:

* their streak
* XP
* level
* progress toward the next milestone

---

# Design

### Decision 015

The product should feel:

* Premium
* Modern
* Friendly
* Calm
* Rewarding

Never childish.

Never noisy.

Never overwhelming.

---

### Decision 016

Animations exist to create delight,

not distraction.

Every animation must serve a purpose.

---

# Product Scope

### Decision 017

The MVP focuses on one habit:

Speak.

Receive feedback.

Improve.

Return tomorrow.

Anything that weakens this loop is postponed.

---

### Decision 018

The MVP will intentionally exclude:

* AI avatars
* Voice cloning
* Team dashboards
* Teacher mode
* Classroom mode
* Courses
* Video generation
* Complex analytics

Focus beats feature count.

---

# Engineering

### Decision 019

Markdown documentation is the source of truth.

Code must follow documentation.

Documentation should never follow implementation.

---

### Decision 020

Lovable is an implementation tool.

It is not allowed to invent product decisions.

Whenever documentation and generated code conflict,

documentation wins.

---

# Future Rule

Every major product decision must be added to this document before implementation begins.
